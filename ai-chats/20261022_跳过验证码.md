## 结论

要“绕过验证码”，通常要改两层：

1. 前端不再要求填写/校验验证码  
2. 后端登录接口不再校验 `captchaId` / `captchaCode`

否则只改前端，后端仍然会拒绝请求。

## 1) 前端需要改的地方

### 登录表单校验
位置在 index.vue

这里的关键点是：

- `loginFormData` 里有 `captchaId` 和 `captchaCode`
- `loginRules` 中把 `captchaCode` 设成了必填
- `handleLoginSubmit` 会先执行 `loginFormRef.value?.validate()`

也就是说，想绕过验证码，最直接就是把这几处改掉：

```js
const loginRules = computed(() => ({
  username: [{ required: true, trigger: "blur", message: "请输入用户名" }],
  password: [
    { required: true, trigger: "blur", message: "请输入密码" },
    { min: 6, message: "密码不能少于6位", trigger: "blur" },
  ],
  // captchaCode: [{ required: true, trigger: "blur", message: "请输入验证码" }],
}));
```

以及：

```js
loginFormData.value.captchaId = "";
loginFormData.value.captchaCode = "";
```

如果只是为了开发调试，可以临时让它不校验。

### 发送登录请求时的字段
位置在 auth.js

这里登录请求会带：

```js
const payload = {
  username: data.username,
  password: data.password,
  captchaId: data.captchaId,
  captchaCode: data.captchaCode,
};
```

如果要绕过，至少要让它不再传验证码参数，或者传空值：

```js
const payload = {
  username: data.username,
  password: data.password,
  // captchaId: data.captchaId,
  // captchaCode: data.captchaCode,
};
```

## 2) 后端必须改的地方

这个项目当前工作区里没有看到后端代码，所以从前端看，真正的校验发生在后端的登录接口中。通常会有类似逻辑：

```python
if not verify_captcha(captcha_id, captcha_code):
    raise HTTPException(status_code=400, detail="验证码错误")
```

或者类似 FastAPI/Flask 的校验代码。  
要绕过验证码，后端要删除/跳过这段校验。

> 也就是说：前端绕过只是“表面绕过”；后端才是最终关口。

## 最小改动方案

如果你只是临时开发环境绕过，建议改成：

- index.vue
  - 删除 `captchaCode` 必填校验
  - `handleLoginSubmit` 不再要求验证码
- auth.js
  - 登录请求不再发送 `captchaId` / `captchaCode`
- 后端登录接口
  - 删除验证码验证逻辑
